## Core library: `src/minipill/`

### [pk.py](src/minipill/pk.py): the model

It tracks five amounts of drug, all in mg:
- **gut**: not yet absorbed
- **central**: in the blood
- **peripheral**: in the tissues
- **eliminated**: cleared from the body
- **first_pass**: lost before reaching the blood

These always add up to the total dose taken, so the solver's accuracy can be checked exactly. For the combined pill there's an optional sixth state, the SHBG level.

### 1. Describing a drug: `dataclass`

[pk.py:45](src/minipill/pk.py#L45) defines `Drug` with `@dataclass(frozen=True)`. A dataclass is a short way to write a class that mostly holds named values. `frozen=True` means the values can't be changed once the object is created, so a drug's parameters can't be overwritten by accident.

Two more Python features show up on `Drug`:
- **`__post_init__`** runs right after an object is created. It's used here to check the inputs, for example that bioavailability `F` is between 0 and 1.
- **`@property`** lets something calculated look like a stored value. For example, `drug.terminal_half_life_h` is worked out from the rate constants each time you read it.

[params.py](src/minipill/params.py) then creates the actual drugs as module-level constants (`NORETHINDRONE = Drug(...)`). A comment on each number says where it came from.

### 2. Simulating blood levels: solving the equations

The model is a set of equations for how fast drug moves between the gut, blood and tissues. [`_rhs`](src/minipill/pk.py#L139) is a small function that returns those rates. SciPy's `solve_ivp` calls it over and over to step forward in time.

The key idea in [`simulate`](src/minipill/pk.py#L169):
1. Collect every pill time into a sorted list of breakpoints.
2. Between two pills, nothing sudden happens, so let the solver run.
3. At each pill, stop, add the dose to the gut, and start again.

This is why a late or missed pill is easy to model: you just change the list of pill times. A `Counter` counts how many pills fall at each time, so two pills at once correctly count as a double dose.

### 3. Fitting parameters to labels: optimization

Most of the drug values were never measured directly. The label only gives summary numbers such as the peak level, the time of the peak and the 24-hour level. The `scripts/fit_*.py` files find parameter values that reproduce those numbers. From [fit_levonorgestrel.py:62](scripts/fit_levonorgestrel.py#L62):

```python
def residuals(p):
    s = summarize(make_drug(p, ka))                          # run the model
    return [np.log(s[k] / v) for k, v in TARGETS.items()]   # how far off from the label?

f = least_squares(residuals, x0)   # SciPy adjusts p until the misses are as small as possible
```

Two tricks are worth knowing:
- **Fitting in log space** (`np.exp(log_params)`): the optimizer works on the logarithm of each parameter. That way the parameters can never go negative, and a 2× miss counts the same whether the value is large or small.
- **Several random starting points** (`rng.normal`): the fit starts from 40 different guesses and keeps the best one. This avoids getting stuck on a poor answer.

`brentq` is simpler: it finds the value where a function equals zero. It's used to work out the absorption rate that puts the peak at exactly 1.2 h.

## Checking the code: tests

[tests/test_pk.py](tests/test_pk.py) uses pytest. Any function named `test_...` is run, and each `assert` must hold. Patterns worth recognizing:
- **`@pytest.mark.parametrize`** runs one test on several drugs.
- **`@pytest.fixture`** (`pack_with_shbg`) runs an expensive simulation once and shares it between tests.
- **Checking against an independent method**: the step-by-step solver is compared with exact formulas (`bateman`, and `exact_single_dose`, which uses matrix eigenvalues). If two unrelated methods agree, both are very likely right.
- **Mass balance**: drug in the gut + blood + tissues + eliminated + lost to first pass must equal the total swallowed.

**Claude:** **Gamma sets how strongly a rise in SHBG slows the clearance of levonorgestrel.** It's the exponent in [pk.py:112](src/minipill/pk.py#L112):

```
k10(t) = k10 × (s0 / S)^gamma
```

- `k10` is the normal rate at which levonorgestrel is cleared from the blood.
- `s0 = 57` nmol/L is the starting SHBG level.
- `S` is the SHBG level at that moment.

As estrogen pushes SHBG up, `s0/S` drops below 1. Gamma decides how much that slows clearance:

| gamma | Clearance when SHBG reaches its plateau (93.5) | Meaning |
|---|---|---|
| 0 | 100% of normal | SHBG has no effect (one of the tests checks this) |
| 1 | 61% | Clearance falls in proportion to SHBG |
| **1.331** (fitted) | **≈ 52%** | Clearance falls faster than SHBG rises |

Roughly, **a 1% rise in SHBG gives about a 1.33% drop in clearance**.

## Where 1.331 comes from

Gamma isn't measured. [fit_shbg.py](scripts/fit_shbg.py) picks the gamma that makes the model's day-6 and day-21 AUCs match the Alesse label. The model gives 48.0 and 66.8 ng·h/mL against 46.0 and 68.3 on the label.

As a separate check, the ≈ 52% matches the label's own clearance change. CL/F falls from 53.7 to 28.4 mL/h/kg between day 1 and day 21, which is 53% of the starting value.

## Why it's above 1

If the only effect were SHBG binding the drug, you might expect a value near 1. But the label's unbound data show that clearance of the *free* drug also falls. That suggests estrogen slows the liver's handling of levonorgestrel in other ways too. So gamma is a lumped number that covers **the whole estrogen effect on clearance**, using SHBG as a stand-in for it. The comment at [params.py:112-113](src/minipill/params.py#L112-L113) notes this.

## Signature and docstring (169–180)

```python
def simulate(drug: Drug, dose_times, dose_mg: float, t_eval, rtol=1e-10, atol=1e-14,
             shbg: SHBGEffect | None = None) -> SimResult:
```

- **`drug`**: the `Drug` object with the rate constants.
- **`dose_times`**: when each pill is taken, in hours, e.g. `[0, 24, 48]`.
- **`dose_mg`**: size of one pill.
- **`t_eval`**: the times you want results at.

- **`shbg`**: either an `SHBGEffect` or `None`, the default, meaning no estrogen effect. `SHBGEffect | None` is a type hint for "one or the other".

## Input checks (181–188)

```python
t_eval = np.asarray(t_eval, dtype=float)
```
Turns whatever was passed (list, range, array) into a NumPy array of decimals.

```python
if t_eval.ndim != 1 or len(t_eval) == 0:
    raise ValueError("t_eval must be a non-empty 1-D array")
if np.any(np.diff(t_eval) <= 0) or t_eval[0] < 0:
    raise ValueError(...)
```
`np.diff` gives the gap between each pair of neighbours. If any gap is ≤ 0, the times aren't strictly increasing. `raise` stops the function with an error message instead of quietly returning nonsense.

```python
dose_times = [float(d) for d in dose_times]
if any(d < 0 for d in dose_times):
    raise ValueError("dose times must be >= 0")
```
The first line is a **list comprehension**: a one-line loop that builds a new list. The second uses `any(...)`, which is `True` if at least one item meets the condition.

## Planning the time segments (190–194)

```python
t_start, t_end = 0.0, t_eval[-1]
```
Two values assigned at once. `t_eval[-1]` is the last element, here 72.

```python
doses_at = Counter(d for d in dose_times if d < t_end)
```
A `Counter` is a dictionary that counts things. Here it gives `{0: 1, 24: 1, 48: 1}`. If two pills are taken at hour 24, it records `{24: 2}`, which is how a double dose works. Pills at or after the end time are dropped, because nothing would happen after them.

```python
off_times = {d + ESTROGEN_HOURS for d in doses_at if d + ESTROGEN_HOURS < t_end} if shbg else set()
```
This only matters with SHBG. For each pill, estrogen switches off 24 h later, so those times are collected. Curly braces make a **set**, which removes duplicates. The trailing `if shbg else set()` is a **conditional expression**: without SHBG, the result is an empty set.

```python
breakpoints = sorted({t_start, t_end, *doses_at, *off_times})
```
**This is the key line.** It builds the list of moments when something changes suddenly. `*doses_at` unpacks the Counter's keys, which are the pill times. The braces remove duplicates and `sorted` puts them in order. In the example this gives `[0, 24, 48, 72]`.

Why split at all? The solver assumes everything changes smoothly. A pill is an instant jump in the gut amount, and estrogen switching off is an instant change in the equations. So the code solves each smooth stretch separately and applies the jumps between them.

```python
args = (drug.ka, drug.F, drug.k10, drug.k12, drug.k21)
```
Bundles the rate constants into a tuple to pass to the equations.

## Setting up storage (196–202)

```python
n_state = 6 if shbg else 5
y = np.zeros(n_state)
if shbg:
    y[5] = shbg.s0
```
`y` is the **current state**: `[gut, central, peripheral, eliminated, first_pass]`, plus SHBG if it's on. Everything starts at zero (no drug yet), except SHBG, which starts at baseline (57).

```python
total_dosed = 0.0
out = np.full((n_state, len(t_eval)), np.nan)
dosed = np.zeros(len(t_eval))
```
`out` is a table with one row per state variable and one column per requested time. It's filled with `nan` ("not a number"), so if any slot were missed it would show up as obviously wrong. `dosed` records the total amount swallowed so far at each time.

## The main loop (204–224)

```python
for i, (a, b) in enumerate(zip(breakpoints[:-1], breakpoints[1:])):
```
- `breakpoints[:-1]` is everything except the last item: `[0, 24, 48]`.
- `breakpoints[1:]` is everything except the first: `[24, 48, 72]`.
- `zip` pairs them up: `(0,24)`, `(24,48)`, `(48,72)`. These are the segments.
- `enumerate` adds a counter `i` (0, 1, 2) so the code can tell which segment is last.

```python
    n = doses_at.get(a, 0)
    y[0] += n * dose_mg
    total_dosed += n * dose_mg
```
**Taking the pill.** If any pills are taken at the start of this segment, their dose goes into the gut (`y[0]`). `.get(a, 0)` returns 0 if no pill is taken at `a`, which is the case at an estrogen-off breakpoint.

```python
    last = i == len(breakpoints) - 2
    mask = (t_eval >= a) & ((t_eval <= b) if last else (t_eval < b))
```
`mask` is an array of True/False values marking which requested times fall in this segment. Each segment covers `[a, b)`, meaning it includes `a` but not `b`, so a time exactly at a pill belongs to exactly one segment. The last segment includes `b` as well, so the final time isn't left out.

A detail: a time exactly at a pill gets the state just *after* the pill is in the gut. The blood level at that instant is unchanged, because absorption hasn't started.

```python
    pts = np.unique(np.concatenate([t_eval[mask], [a, b]]))
```
The times to ask the solver for: this segment's requested times plus both ends. `np.unique` also sorts them. Including `b` guarantees the solver reports the state at the end of the segment, which becomes the start of the next one.

```python
    if shbg:
        on = any(d <= a < d + ESTROGEN_HOURS for d in doses_at)
        sol = solve_ivp(_rhs_shbg, (a, b), y, t_eval=pts, args=(*args, shbg, on),
                        method="LSODA", rtol=rtol, atol=atol)
    else:
        sol = solve_ivp(_rhs, (a, b), y, t_eval=pts, args=args, method="LSODA", rtol=rtol, atol=atol)
```
**Solving the equations.** `solve_ivp` (solve an initial value problem) is given:
- the function with the rates (`_rhs` or `_rhs_shbg`)
- the time span `(a, b)`
- the starting state `y`
- the times to report (`pts`)
- extra arguments passed through to the rates function (`args`)

`LSODA` is a solver that switches automatically between methods for fast-changing and slow-changing equations.

With SHBG, `on` asks whether any pill was taken in the 24 h before this segment starts. Checking only at the start is enough, because every on/off switch is a breakpoint, so estrogen can't change partway through a segment.

```python
    if not sol.success:
        raise RuntimeError(f"ODE solver failed on [{a}, {b}]: {sol.message}")
```
If the solver fails, stop loudly. The `f"..."` is an **f-string**, which inserts values into text.

```python
    idx = np.searchsorted(pts, t_eval[mask])
    out[:, mask] = sol.y[:, idx]
```
`pts` contains the extra points `a` and `b`, so the solver's columns don't line up one-to-one with the requested times. `searchsorted` finds where each requested time sits in `pts`. The second line copies those columns into the right slots of `out`. `[:, mask]` means "all rows, the columns where mask is True".

```python
    dosed[mask] = total_dosed
    y = sol.y[:, -1].copy()
```
Record the cumulative dose for these times. Then take the state at the end of the segment (`-1` is the last column) as the start of the next one.

`.copy()` matters here. Without it, `y` would share memory with the solver's output, so `y[0] += dose` next time round would also change `sol.y`.

## Packaging the result (226–231)

```python
gut, central, peripheral, eliminated, first_pass = out[:5]
```
**Unpacking**: the first five rows of `out` go into five named variables.

```python
return SimResult(
    t=t_eval, gut=gut, central=central, peripheral=peripheral, eliminated=eliminated,
    first_pass=first_pass, conc=central / drug.V_L, dosed=dosed,
```

Everything goes into the `SimResult` dataclass so callers can write `result.conc` instead of remembering row numbers. Concentration is calculated once here: amount in the blood ÷ blood volume, in mg/L. SHBG is included only if it was simulated.

## In one sentence

Split time at every pill and every estrogen switch. At each split, add the pill to the gut. Let SciPy solve the smooth equations up to the next split. Carry the end state forward, and copy out the requested time points along the way.

| Value | What it is | Rate constant? |
|---|---|---|
| `ka` | absorption from gut to blood, 1/h | yes |
| `F` | fraction that survives first pass, 0–1 | **no**, it's a fraction with no units |

Two fields of `Drug` are left out:
- **`name`**: only a label.
- **`V_L`** (blood volume): the equations work in **amounts** (mg), not concentrations, so volume isn't needed while solving. It's used once at the end to turn amount into concentration: `conc = central / drug.V_L`.

**It's one drug per call.** `simulate` handles a single drug, so `args` holds just that drug's values. The comparison page calls `simulate` separately for norethindrone and for levonorgestrel.

**With SHBG, two more items are added** at [pk.py:214](src/minipill/pk.py#L214): `args=(*args, shbg, on)`. The `*args` unpacks the five values, then the `SHBGEffect` object and the estrogen on/off flag are appended.

**How they reach the equations.** `solve_ivp` calls the rates function as `_rhs(t, y, *args)`, so the five values land in its parameters in that order:

```python
def _rhs(t, y, ka, F, k10, k12, k21):
```

That's why the order in `args` must match the order in `_rhs`. Swapping two would silently give wrong results, not an error.

**Student:** so the main loop puts times through each equation of the pill and then spits out the concentration?

**Claude:** Close, but the loop doesn't plug times into a formula, and there isn't a separate equation for each pill.

**There's one set of equations for the drug.** [`_rhs`](src/minipill/pk.py#L139) doesn't give the amount of drug at a given time. It gives how fast each amount is **changing right now**, based on the current amounts. For example, the gut empties at `ka × gut` per hour. Pills don't get their own equations. A pill is just an amount dropped into the gut.

**The loop moves forward through time, one segment at a time.** For each stretch between breakpoints:

1. **Pill taken?** Add the dose to the gut.
2. **Solve.** `solve_ivp` starts from the current amounts and takes many tiny steps. At each step it asks `_rhs` how fast things are changing, moves forward a little, and repeats. That's how it gets the amounts across the segment.
3. **Record.** Save the amounts at the requested times in this segment.
4. **Carry forward.** The amounts at the end of the segment become the start of the next one.

So drug left over from earlier pills is carried along. When the 24-hour pill arrives, the blood already contains drug from the first one, and the new dose adds on top. That's how build-up and late pills come out of the model without any special handling.

**Concentration isn't calculated in the loop.** The loop only tracks amounts in mg in each compartment. After the loop ends, one line turns blood amount into concentration for all times at once:

```python
conc = central / drug.V_L
```

In short: the loop **advances the amounts through time, segment by segment, adding pills as they come**, and concentration is worked out at the end.

**Student:** explain the function bateman and the formula it is based on

**Claude:** [`bateman`](src/minipill/pk.py#L234-L243) gives the **exact blood concentration after one pill**, for a one-compartment drug, using a ready-made formula instead of the step-by-step solver.

## The formula

$$
C(t) = \frac{F \cdot D \cdot k_a}{V\,(k_a - k)}\left(e^{-k t} - e^{-k_a t}\right)
$$

| Symbol | In the code | Meaning |
|---|---|---|
| D | `dose_mg` | pill size |
| F | `drug.F` | fraction reaching the blood |
| k_a | `drug.ka` | absorption rate |
| k | `drug.k10` | elimination rate |
| V | `drug.V_L` | blood volume |

It's named after Harry Bateman, who solved the same mathematics in 1910 for chains of radioactive decay. One substance turning into another, which then decays, is the same setup as drug moving from gut to blood and then being eliminated.

## Where it comes from

With one compartment, the equations from `_rhs` reduce to two:

- **Gut:** dG/dt = −k_a·G. This empties exponentially, so G(t) = D·e^(−k_a t).
- **Blood:** dA/dt = F·k_a·G − k·A. Drug flows in from the gut and is removed in proportion to how much is there.

Substituting the gut solution into the blood equation and solving gives the formula above, after dividing by V to get concentration.

## Why it has that shape

The curve is the **difference of two exponentials**:

- **e^(−kt)** falls slowly. This is elimination.
- **e^(−k_a t)** falls quickly. This is absorption finishing.

At t = 0 they're equal, so C = 0 because nothing has been absorbed yet. Early on, the fast term drops away quickly, so the gap grows and the level rises. Once absorption is basically done, only e^(−kt) is left. That gives the slow exponential fall, which sets the half-life.

The peak is where the rise turns into the fall. Setting the slope to zero gives

$$
t_{max} = \frac{\ln(k_a / k)}{k_a - k}
$$

which is exactly the [`tmax`](src/minipill/pk.py#L268) function. `ka_from_tmax` runs it in reverse.

## The code, line by line

```python
if drug.n_compartments != 1:
    raise ValueError("bateman() is for one-compartment drugs; use exact_single_dose()")
```
The formula only holds without a tissue compartment, so two-compartment drugs are refused.

```python
t = np.asarray(t, dtype=float)
ka, k = drug.ka, drug.k10
```
Converts the times to an array and gives the two rates short names.

```python
if np.isclose(ka, k):
    raise ValueError("Bateman formula needs ka != k10")
```
If k_a = k, the formula divides by zero. The true curve still exists in that case (it becomes F·D·k·t·e^(−kt)/V), but this function doesn't handle it. `isclose` also catches values that are only nearly equal, where rounding errors would be huge.

```python
c = drug.F * dose_mg * ka / (drug.V_L * (ka - k)) * (np.exp(-k * t) - np.exp(-ka * t))
```
The formula itself. Because `t` is a NumPy array, this calculates every time point in one go.

```python
return np.where(t >= 0, c, 0.0)
```
Before the pill (t < 0) the formula would give nonsense, so those times are set to 0. `np.where(condition, a, b)` picks `a` where the condition is true and `b` elsewhere.

## Why the project has it

The model's simulations don't use it. It's a **check**: [test_single_dose_matches_bateman](tests/test_pk.py#L31) runs `simulate` on one pill and confirms the result matches this formula. Two completely different methods, step-by-step solving and an exact formula, give the same numbers, which shows the solver is set up correctly.

Two-compartment drugs have no simple formula like this, so [`exact_single_dose`](src/minipill/pk.py#L246) does the same job for them using matrix maths.

**A link to your earlier question.** Integrating the Bateman curve over all time gives the total exposure, AUC = F·D / (V·k) = F·D / clearance. That's the same relationship [fit_levonorgestrel.py:52](scripts/fit_levonorgestrel.py#L52) uses with `clearance_L_per_h`.

**Student:** can you explain exact_single_dose

**Claude:** [`exact_single_dose`](src/minipill/pk.py#L246-L265) does the same job as `bateman`: the exact blood concentration after one pill. The difference is that it also works for **two-compartment** drugs, where no simple textbook formula exists. It gets there with matrix algebra instead.

## The idea in one dimension first

The simplest equation of this kind is

  dy/dt = a·y  →  y(t) = y₀·e^(at)

Something whose rate of change is proportional to itself grows or decays exponentially.

## The same idea with three compartments

Gut, blood and tissues affect each other, so their equations are linked. You can write all three as one **matrix equation**:

$$
\frac{d}{dt}\begin{bmatrix}G\\A_1\\A_2\end{bmatrix}
=
\underbrace{\begin{bmatrix}
-k_a & 0 & 0\\
F k_a & -(k_{10}+k_{12}) & k_{21}\\
0 & k_{12} & -k_{21}
\end{bmatrix}}_{M}
\begin{bmatrix}G\\A_1\\A_2\end{bmatrix}
$$

Each row is one line of `_rhs`:
- **Gut row**: it only drains, at −k_a·G.
- **Blood row**: gains F·k_a·G from the gut, loses (k₁₀ + k₁₂)·A₁ to elimination and tissues, and gains k₂₁·A₂ back from the tissues.
- **Tissue row**: gains k₁₂·A₁ and loses k₂₁·A₂.

The solution looks just like the 1-D case, with a matrix in the exponent: y(t) = e^(Mt)·y₀. Raising e to a matrix isn't something you can calculate directly, so the code uses a standard trick.

## The trick: eigenvalues and eigenvectors

An **eigenvector** of M is a particular mix of gut, blood and tissue amounts that keeps the same proportions over time. It just shrinks at its own single rate, which is its **eigenvalue**.

This matrix has three of these, with rates −k_a, −α and −β: the absorption rate and the fast and slow decay rates from `disposition_rates`. Any starting state can be written as a combination of the three. Each part then decays at its own rate, so the blood amount is a **sum of three exponentials**:

$$
A_1(t) = w_1 e^{-k_a t} + w_2 e^{-\alpha t} + w_3 e^{-\beta t}
$$

The Bateman formula is the one-compartment version of this, with two exponentials. The second compartment adds one more.

## The code, line by line

```python
t = np.asarray(t, dtype=float)
ka, F, k10, k12, k21 = drug.ka, drug.F, drug.k10, drug.k12, drug.k21
```
Converts the times to an array and unpacks the parameters.

```python
M = np.array([
    [-ka, 0.0, 0.0],
    [F * ka, -(k10 + k12), k21],
    [0.0, k12, -k21],
])
```
The matrix above. "Eliminated" and "first pass" are left out because they don't feed back into anything; they only collect drug. Including them would add two zero eigenvalues, which are equal, and that would trip the next check.

```python
lam, P = np.linalg.eig(M)
```
NumPy finds the eigenvalues (`lam`, three numbers) and eigenvectors (`P`, a 3×3 matrix with one eigenvector per column).

```python
if np.min(np.abs(np.subtract.outer(lam, lam)) + np.eye(3)) < 1e-9:
    raise ValueError("repeated rates: exact solution needs distinct ka, alpha, beta")
```
This checks that no two rates are equal.
- `np.subtract.outer(lam, lam)` builds a 3×3 table of every difference λᵢ − λⱼ.
- The diagonal compares each rate with itself, so it's always 0. Adding `np.eye(3)`, the identity matrix, turns those into 1 so they don't count.
- If any remaining difference is close to 0, two rates are equal. The eigenvector method then breaks down, just as Bateman divides by zero when k_a = k.

```python
coef = np.linalg.solve(P, [dose_mg, 0.0, 0.0])
```
At t = 0 the whole dose is in the gut and nothing is in the blood or tissues, so the starting state is `[dose, 0, 0]`. This splits that starting state into its three eigenvector parts. `solve` calculates P⁻¹·y₀ without building the inverse, which is more accurate.

F isn't applied here, because it's already inside M as the F·k_a entry.

```python
tt = np.clip(t, 0, None).ravel()
```
`clip` raises negative times to 0. Those are zeroed at the end anyway, and this stops `exp` from producing huge numbers. `ravel` flattens the times into a simple 1-D list.

```python
central = ((P[1] * coef) @ np.exp(np.outer(lam, tt))).reshape(t.shape)
```
This builds the sum of three exponentials, in three steps:
- `P[1] * coef` takes row 1 of P (the blood compartment) times each part's size. That gives the three weights w₁, w₂, w₃.
- `np.exp(np.outer(lam, tt))` is a 3 × N table of e^(λᵢ·t), one row per rate and one column per time.
- `@` is matrix multiplication. For each time it computes w₁e^(λ₁t) + w₂e^(λ₂t) + w₃e^(λ₃t).

`reshape` restores the original shape of `t`.

```python
return np.where(t >= 0, np.real(central) / drug.V_L, 0.0)
```
Divide by blood volume to get concentration, and return 0 before the pill. `np.real` is a safety step: eigenvalue routines can return complex numbers, and here any imaginary part is zero.

## Why it's used

- **As a check**: [test_two_compartment_single_dose_matches_exact](tests/test_pk.py#L45) confirms that `simulate` matches it. With k₁₂ = k₂₁ = 0 it also matches `bateman` ([test_exact_solution_matches_bateman](tests/test_pk.py#L39)), so all three methods agree.
- **For fitting**: the fitting scripts import it. It's a single formula with no step-by-step solving, so it's fast enough for an optimizer that has to try thousands of parameter sets.

**Student:** how is the clearance multiplier calculated

**Claude:** It takes two steps: work out one number, 0.49, from the study, then turn the BMI you enter into a fraction of that change.

## Step 1: The 0.49, from Edelman 2009

The study measured two things for levonorgestrel:
- **Half-life**: 25.6 h at normal BMI, 52.1 h in obese women.
- **Volume of distribution**: no difference between the groups.

Those three quantities are linked:

$$
V = \frac{CL \times t_{1/2}}{\ln 2}
\quad\Longrightarrow\quad
CL = \frac{\ln 2 \times V}{t_{1/2}}
$$

V is the same in both groups and ln 2 is a constant, so clearance is simply proportional to 1 ÷ half-life. The ratio of the two groups is therefore

$$
\frac{CL_{obese}}{CL_{normal}} = \frac{t_{1/2,\,normal}}{t_{1/2,\,obese}} = \frac{25.6}{52.1} = 0.491
$$

Twice the half-life with the same volume means the body clears the drug at half the rate. That's `OBESE_CLEARANCE_RATIO` in [params.py](src/minipill/params.py).

## Step 2: From your BMI to a multiplier

The study only has two points: BMI 21.9 gives ×1 and BMI 37.3 gives ×0.491. `clearance_factor_for_bmi` fills in the rest:

```python
frac = np.clip((bmi - 21.9) / (37.3 - 21.9), 0.0, 1.0)
return 0.491 ** frac
```

**`frac`** is how far your BMI sits between the two groups, on a 0-to-1 scale:
- BMI 21.9 gives 0, BMI 37.3 gives 1, and BMI 29.6 (halfway) gives 0.5.
- `np.clip` stops it at 0 below 21.9 and at 1 above 37.3. That's what keeps clearance at ×1 for lower BMIs and at ×0.491 for higher ones.

**`0.491 ** frac`** raises 0.491 to that power. With frac = 0 the result is 1, and with frac = 1 it's 0.491.

### Worked examples

| BMI | frac | Multiplier | Clearance |
|---|---|---|---|
| 18 | 0 (clipped) | 0.491⁰ | 100% |
| 21.9 | 0 | 0.491⁰ | 100% |
| 25 | 0.20 | 0.491^0.20 | 87% |
| 29.6 | 0.50 | √0.491 | 70% |
| 33 | 0.72 | 0.491^0.72 | 60% |
| 37.3 | 1 | 0.491¹ | 49% |
| 45 | 1 (clipped) | 0.491¹ | 49% |

## Why a power and not a straight line

With a power, **each extra BMI point multiplies clearance by the same amount**: ×0.955, about 4.5% less per point. That matches how body changes usually act on clearance, by percentages rather than fixed amounts.

A straight line from 1 to 0.491 would be just as consistent with the two data points. It would give 75% at the midpoint instead of 70%. The study can't tell the two apart, which is why the in-between curve is listed as an assumption.

## Step 3: Using the multiplier

Clearance is `k10 × V_L`, so levonorgestrel's clearance goes from 2.84 to 1.40 L/h. Everything else in the model stays the same.

## Line 150: how far between the two groups

```python
frac = np.clip((np.asarray(bmi, dtype=float) - BMI_REFERENCE) / (BMI_OBESE - BMI_REFERENCE), 0.0, 1.0)
```

Read it from the inside out:

**`np.asarray(bmi, dtype=float)`** turns the input into a NumPy array of decimals. You can pass one number (`29.6`) or a whole list or array of BMIs, and the rest of the line works on all of them at once.

**`(... - BMI_REFERENCE) / (BMI_OBESE - BMI_REFERENCE)`** measures how far the BMI sits along the 21.9 → 37.3 range. The range is 15.4 BMI points wide, so:

```
bmi        : [18.   21.9   25.   29.6   33.   37.3   45. ]
raw frac   : [-0.253  0.  0.201  0.5   0.721  1.    1.5 ]
```

BMI 18 is below the range, so it comes out negative. BMI 45 is beyond it, so it comes out above 1.

**`np.clip(..., 0.0, 1.0)`** forces every value into 0 to 1:

```
clipped    : [0.    0.    0.201  0.5   0.721  1.    1.  ]
```

That single call is what makes the curve flat at both ends. Below BMI 21.9 you get the label values unchanged; above 37.3 you get the obese group's value and no further extrapolation.

## Line 151: the multiplier

```python
return OBESE_CLEARANCE_RATIO ** frac
```

`**` means "to the power of", and NumPy applies it to each value:

```
factor     : [1.    1.    0.867  0.701  0.599  0.491  0.491]
```

- frac 0 gives 0.491⁰ = **1**, normal clearance.
- frac 1 gives 0.491¹ = **0.491**, the obese group.
- frac 0.5 gives 0.491^0.5 = √0.491 = **0.701**.

Because it's a power, each BMI point multiplies clearance by the same amount: 0.491^(1/15.4) = **0.955**, about 4.5% less per point.

## What comes back

With one number in, you get one number back: `f(29.6)` returns `0.7009…`. Its type is `numpy.float64`, NumPy's version of a decimal, which behaves like a normal float. With an array in, you get an array back. The test `test_clearance_factor_for_bmi` uses that to check 200 BMIs at once and confirm the curve never goes up.

## 3. `np.asarray`: it's about the input, not the dictionary

The dictionary is only used for the constants above the function. `np.asarray` acts on **`bmi`, the value passed into the function**. It does two things:

- **It lets lists work.** If someone passes a plain Python list, `[25, 30] - 21.9` is an error, because Python lists can't do arithmetic. `np.asarray` turns the list into a NumPy array, which subtracts 21.9 from every item.
- **`dtype=float` makes everything decimals**, so a whole number like `30` is treated as `30.0`.

So "turn the input into decimals" is half of it. The other half is "turn it into an array so the maths works on many BMIs at once".

- **`frac`** answers *where* the BMI is between the two groups (clipped to 0–1).
- **`OBESE_CLEARANCE_RATIO`** answers *how big* the effect is.
- **`**`** combines them.
